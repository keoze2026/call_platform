# CH-601 - Claude's answer never empty: room to think, low effort, answer in our schema (Server B host)

5 Nov, first dry run after CH-600: one call of three -
`FAILED - the LLM did not answer in JSON: ''`.

Cause: Claude Haiku 5.5 thinks before it answers (adaptive thinking is on by
default) and the thinking counts against `max_tokens`. CH-555 allowed 300
tokens - on a harder call the thinking used them all and no text was left.

- `max_tokens` 300 -> 4000 (room for the thinking and the answer).
- `output_config.effort` = AI_LLM_EFFORT (`low`): enough for this decision,
  fewer thinking tokens to pay for. `AI_LLM_EFFORT=` (empty) sends none.
- `output_config.format` json_schema (structured outputs): the answer is
  always JSON with `label` one of our labels, `confidence`, `summary`.
  `AI_LLM_STRUCTURED=off` sends none (the instructions still ask for JSON).
- An empty answer now says why: `Claude gave no answer (stop_reason: ...)`.
- Confidence is clamped to 0-100; the label is read in any letter case.
- The pre-check sends the same request (schema and effort included), so if
  the model ever refuses either, the run stops before anything is
  transcribed and the log names the setting to switch off.

Tests: routing/test_ai_accuracy.py (+2).
